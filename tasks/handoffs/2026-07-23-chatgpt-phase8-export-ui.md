## What to build

### Target sheet structure (implement all except "Steel sub-lines")

**Sheet 1 — "Cover" (Front Page equivalent)**
- Reference block:
  - Work: `tender_number` + `work_description`
  - LOA No. / LOA Date: from contract
  - Contractor: `contractor_name`
  - Base month
  - Railway zone
- Per-bill summary table: Bill No. | Quarter | W Amount | Total PVC
  - Pull from `pvc_runs` + `running_bills` for all approved runs on this contract (not just the current run)
  - Current run row highlighted (bold or fill)
- Cell at bottom: generated-by note ("Generated by TenderAudit")

**Sheet 2 — "Bill" (existing single sheet, refactored)**
- Exactly as it is now after the WS-B parity pass:
  - Summary block: Run ID, Status, Quarter, Tender, Contractor, Zone, Base Month, Approved By
  - Component table: Category | W | Avg Index | Base Index | Weight | PVC Amount
  - SUM total row
- Keep the existing 4 test pins passing

**Sheet 3 — "W Derivation"**
- The W derivation steps from the run result:
  - On-account (gross) amount
  - Less: technical withheld (from `w_derivation.technical_withheld`, can be 0)
  - Less: recoveries affecting PVC (from `w_derivation.recoveries_affecting_pvc`)
  - **= W (eligible amount)**
  - Carry-forward from previous run (if any)
  - Note: these values are in `pvc_run_outputs` / returned by the engine result
- This is read-only derived data — source it from `pvc_runs.lines_snapshot` or recompute from run data

### Data access pattern

The export route handler in `backend/api/exports.py` already receives `run_id` and the approved run row. The `services/exports.py` generator receives:
- `run`: the `pvc_runs` row (has `total_pvc`, `negative_carry_forward`, `quarter_used`, `lines_snapshot`)
- `components`: list of `pvc_components` rows

For the Cover sheet you need the contract and all runs on it. The export route currently fetches only the run. You'll need to either:
1. Pass the contract + all runs to `generate_excel` (cleanest — add parameters), OR
2. Accept a session in `generate_excel` and query inside (less pure — current pattern prefers pure generators)

**Recommended:** option 1. Update the route handler in `exports.py` to query the contract and sibling runs, pass them to `generate_excel`. Keep `generate_excel` a pure function.

## Architecture note

`generate_excel` is currently a pure function: `(run: dict, components: list[dict]) -> bytes`. The recommended signature after this change:

```python
def generate_excel(
    run: dict,
    components: list[dict],
    contract: dict | None = None,
    all_runs: list[dict] | None = None,
) -> bytes:
```

Default `None` keeps backward compatibility with the existing tests, which don't pass contract/runs. The Cover sheet is skipped (or shows a stub) when `contract` is `None`.

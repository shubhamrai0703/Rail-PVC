## 3. Runtime-Only Click-Paths

### 3a. Calculate → Supersede → Approve → Export (for a new bill)

1. Open `/contracts/<cid-A>/bills/<bid-A3>` (Bill 3, status Draft).
2. Click **Calculate PVC** → new run created, status=Calculated.
3. Click **Recalculate** on the same bill → prior Calculated run becomes Superseded; new Calculated run appears.
4. In run detail, click **Approve Run** → status transitions to Approved.
5. Click **Export Excel** / **Export PDF** → file downloads. Verify content matches W and component values.
6. Attempt **Recalculate** again → confirmed the Approved run is untouched (trigger blocks update); a new Calculated run is created alongside it.

### 3b. Blocked-run error (Contract B)

1. Open `/contracts/<cid-B>/bills/<bid-B1>`.
2. Click **Calculate PVC**.
3. Verify the UI shows the engine's validation error:
   `"undecided extra items block the run: [<item_id>]"`
4. Navigate to **Extra Items** for Contract B.
5. Set B-ENS-LMP to **Eligible=TRUE** (include in W) or **Eligible=FALSE** (exclude).
6. Recalculate → run succeeds.

### 3c. Index Manager — add monthly observation (Scenario G)

1. Log in as the admin user (promoted by seed script).
2. Navigate to **Index Manager** (`/indices`).
3. Click on **steel_tmt** series.
4. Click **Add Observation** → enter month `2026-02`, value `54500`.
5. Row appears in the table.
6. Verify it does NOT replace an existing observation (only new months permitted via UI).

### 3d. Document upload (Scenario H)

Prepare two placeholder files locally (a tiny PDF and a tiny `.xlsx`).

1. Open `/contracts/<cid-A>/documents`.
2. Click **Upload** → choose the PDF → select type=`agreement` → confirm.
3. Row appears with original filename and upload timestamp.
4. Repeat for each remaining type: `mb`, `bill`, `recovery`, `workbook`, `other`.
5. Confirm 6 entries total (or 12 if the seed placeholder rows are still visible).

> **Note:** Documents are stored in Supabase Storage. Ensure the Supabase project
> has a `documents` bucket and the backend `.env` contains valid Supabase credentials.

## 4. Teardown

To remove all test-tenant data:

```sql
-- Delete cascades to contracts → schedules → items → bills → bill_lines
-- → recoveries → pvc_runs → pvc_components → extra_item_decisions
-- → carry_forwards → documents (via ON DELETE CASCADE)
DELETE FROM contracts WHERE tenant_id = 'a0a0a0a0-1111-4000-8000-000000000001';

-- Remove carry_forwards that don't cascade (no FK ON DELETE CASCADE from tenant):
DELETE FROM carry_forwards WHERE contract_id IN (
    SELECT id FROM contracts WHERE tenant_id = 'a0a0a0a0-1111-4000-8000-000000000001'
);

-- If you want to remove the tenant itself:
DELETE FROM tenants WHERE id = 'a0a0a0a0-1111-4000-8000-000000000001';
```

> Replace the UUID with `SEED_TENANT_ID` if you used a custom value.
> Approved PVC runs are immutable via the DB trigger but **can** be deleted directly
> since the trigger fires only on UPDATE, not DELETE.

## 5. W-Derivation Reference (for assertions)

The formula the engine uses for each bill (GCC 46A.9):

```
W = on_account_amount
    − cement_amount
    − (steel_angles_amount + CF_angles_prorated)
    − (steel_plates_amount + CF_plates_prorated)
    − (steel_tmt_amount + CF_tmt_prorated)
    − (steel_other_amount + CF_other_prorated)
    − technical_withheld          ← SUM(recoveries WHERE affects_pvc_base=TRUE)
    − excluded_extra_items        ← SUM(ExtraItemDecision WHERE eligible=FALSE)
```
